## 유저 스토리란?

기능을 **사용자 관점**에서 서술한 짧은 문장입니다.
개발자가 "무엇을 왜 만들어야 하는지"를 이해하기 위해 사용합니다.

**작성 형식:**
> 나는 **[누구]** 로서, **[무엇을]** 하고 싶다, 왜냐하면 **[이유/얻는 것]** 때문이다.

각 스토리에는 **인수 조건 (Acceptance Criteria)** 이 함께 작성됩니다.
인수 조건이란, 이 기능이 "완성됐다"고 판단하기 위한 구체적인 조건 목록입니다.
개발자와 기획자가 "이 조건을 모두 만족하면 이 기능은 완성"이라고 합의하는 기준입니다.

**우선순위 기준:**
- `Must Have (필수)` — v1 출시에 반드시 필요한 기능
- `Should Have (중요)` — 중요하지만 없어도 출시는 가능한 기능
- `Nice to Have (있으면 좋음)` — 시간이 허락할 때 포함하면 좋은 기능

## 기능 1: 거래 내역 입력 (Transaction Entry)

---

**US-001**
**제목:** 기본 거래 추가
**스토리:** 나는 **사용자**로서, 수입 또는 지출 거래를 입력하고 싶다, 왜냐하면 내 재무 내역을 기록으로 남기고 싶기 때문이다.
**우선순위:** Must Have (필수)

**인수 조건:**
- [ ] 금액, 카테고리, 귀속 월, 결제 수단, 메모를 입력할 수 있다
- [ ] 거래 유형을 수입 또는 지출로 선택할 수 있다
- [ ] 결제 수단이 **신용카드**인 경우: 거래 날짜와 카드의 사용기간을 기반으로 현금 유출일(결제일)이 **자동 계산**된다 — 사용자가 직접 입력하지 않아도 됨
- [ ] 결제 수단이 **은행 계좌**인 경우: 현금 유출일 = 거래일로 자동 처리된다
- [ ] 저장 후 거래 내역 목록에 해당 거래가 나타난다
- [ ] 저장 즉시 대시보드 합계가 업데이트된다

---

**US-002**
**제목:** 일시불 지출 월별 분할 입력
**스토리:** 나는 **사용자**로서, 한 번에 발생한 큰 지출을 여러 달에 걸쳐 나눠 입력하고 싶다, 왜냐하면 발생주의 뷰에서 월별로 정확한 금액이 표시되길 원하기 때문이다.
**우선순위:** Must Have (필수)

**인수 조건:**
- [ ] 총 금액, 분할 개월 수, 시작 월을 직접 선택할 수 있다
- [ ] 시스템이 금액을 균등하게 나눠 각 달의 발생주의 뷰에 반영한다
- [ ] 현금 뷰에서는 실제 결제일에 전체 금액이 한 번에 표시된다
- [ ] 거래 상세 보기에서 분할된 모든 달의 내역을 확인할 수 있다

---

**US-003**
**제목:** 분할 거래 금액 수정
**스토리:** 나는 **사용자**로서, 분할 거래의 총 금액을 변경하고 싶다, 왜냐하면 입력 실수를 수정하거나 금액이 바뀐 경우 업데이트해야 하기 때문이다.
**우선순위:** Must Have (필수)

**인수 조건:**
- [ ] 분할 거래의 금액을 수정하면 앱이 묻는다: "모든 달에 적용할까요, 아니면 이후 달에만 적용할까요?"
- [ ] "모든 달"을 선택하면 전체 분할 달의 금액이 새로 균등하게 재계산된다
- [ ] "이후 달에만"을 선택하면 과거 달은 그대로 유지되고, 남은 달만 재계산된다
- [ ] 수정된 금액이 대시보드에 즉시 반영된다

---

**US-004**
**제목:** 영수증 사진 첨부
**스토리:** 나는 **사용자**로서, 거래에 영수증 사진을 첨부하고 싶다, 왜냐하면 구매 증빙을 거래 기록과 함께 보관하고 싶기 때문이다.
**우선순위:** Should Have (중요)

**인수 조건:**
- [ ] 거래당 사진 1장을 내 기기에서 업로드할 수 있다
- [ ] 지원 형식: JPG, PNG, HEIC. 최대 파일 크기: 5 MB
- [ ] 사진은 서버에 저장되며, 저장 시 암호화된다
- [ ] 거래 상세 보기에서 첨부된 사진을 확인할 수 있다
- [ ] 첨부 사진을 교체하거나 삭제할 수 있다
- [ ] 사진이 없어도 거래는 정상적으로 저장된다
- [ ] 업로드 실패 시 (형식 오류, 크기 초과, 네트워크 오류) 명확한 오류 메시지가 표시되며, 거래는 사진 없이 정상 저장된다

---

**US-005**
**제목:** 거래 수정 및 삭제
**스토리:** 나는 **사용자**로서, 저장된 거래를 수정하거나 삭제하고 싶다, 왜냐하면 입력 오류를 고치거나 중복 항목을 제거해야 하기 때문이다.
**우선순위:** Must Have (필수)

**인수 조건:**
- [ ] 거래를 탭/클릭하면 상세 보기가 열린다
- [ ] 모든 항목을 수정하고 저장할 수 있다
- [ ] 확인 팝업("정말 삭제하시겠습니까?") 후 거래를 삭제할 수 있다
- [ ] 삭제 후 거래가 내역에서 사라지고 대시보드 합계가 업데이트된다

---

**US-026**
**제목:** 수입 월별 분할 입력
**스토리:** 나는 **사용자**로서, 일회성 수입(예: 연말 보너스)을 여러 달에 걸쳐 나눠 기록하고 싶다, 왜냐하면 발생주의 뷰에서 월별로 정확한 수입이 표시되어야 의미 있는 분석이 가능하기 때문이다.
**우선순위:** Must Have (필수)

**인수 조건:**
- [ ] 수입 거래 추가 시 월별 분할을 선택할 수 있다
- [ ] 총 금액, 분할 개월 수, 시작 월을 직접 선택할 수 있다 (US-002와 동일 흐름)
- [ ] 시스템이 금액을 균등하게 나눠 각 달의 발생주의 뷰에 반영한다
- [ ] 현금 뷰에서는 실제 입금일에 전체 금액이 한 번에 표시된다
- [ ] 거래 상세 보기에서 분할된 모든 달의 내역을 확인할 수 있다
- [ ] 분할 금액 수정 시 US-003과 동일하게 "모든 달 / 이후 달만" 선택지가 표시된다

---

**US-027**
**제목:** 사용자 정의 카테고리 관리
**스토리:** 나는 **사용자**로서, 카테고리를 직접 추가/이름 변경/삭제하고 싶다, 왜냐하면 내 지출 패턴에 맞게 분류 체계를 구성하고 싶기 때문이다.
**우선순위:** Must Have (필수)

**인수 조건:**
- [ ] 카테고리 설정 페이지에서 새 카테고리를 추가할 수 있다
- [ ] 기본/사용자 정의 카테고리 모두 이름을 변경할 수 있다 — 기존 거래에 자동 반영됨
- [ ] 사용자 정의 카테고리를 삭제하면 해당 카테고리의 거래는 "기타"로 자동 이동된다
- [ ] 기본 카테고리는 삭제할 수 없지만 선택 목록에서 숨길 수 있다
- [ ] 거래 입력 드롭다운에 기본 카테고리와 사용자 정의 카테고리가 함께 표시된다

---

**US-028**
**제목:** 거래 내역 필터링 및 검색
**스토리:** 나는 **사용자**로서, 거래 내역을 필터링하거나 검색하고 싶다, 왜냐하면 전체 목록을 스크롤하지 않고 특정 거래를 빠르게 찾고 싶기 때문이다.
**우선순위:** Should Have (중요)

**인수 조건:**
- [ ] 날짜 범위, 카테고리, 결제 수단, 거래 유형(수입/지출), 금액 범위로 필터링할 수 있다
- [ ] 메모/내용에 포함된 키워드로 검색할 수 있다
- [ ] 여러 필터를 조합할 수 있다 (예: "식비" + "최근 3개월")
- [ ] 필터 변경 즉시 목록이 업데이트된다
- [ ] 활성화된 필터가 목록 상단에 표시되며, 한 번의 클릭으로 모두 초기화할 수 있다

## 기능 2: 결제 수단 관리 (Payment Method Management)

---

**US-006**
**제목:** 신용카드 등록 (결제일 + 사용기간 설정)
**스토리:** 나는 **사용자**로서, 신용카드를 등록하고 결제일과 사용기간 범위를 함께 설정하고 싶다, 왜냐하면 앱이 거래 날짜를 보고 어느 결제 주기에 속하는지 자동으로 판단해 정확한 현금 유출 시점을 계산해주길 원하기 때문이다.
**우선순위:** Must Have (필수)

**인수 조건:**
- [ ] 카드 등록 시 다음 세 가지를 입력할 수 있다:
  - 카드 이름 (예: "카카오뱅크 비자")
  - 사용기간 시작일 (예: 매월 1일)
  - 사용기간 마감일 (예: 매월 말일) 및 결제일 (예: 다음 달 25일)
- [ ] 시스템이 거래 날짜와 사용기간을 비교해 해당 거래가 어느 결제 주기에 속하는지 자동 분류한다
- [ ] 자동 분류된 결제 주기를 기반으로 실제 현금 유출일(결제일)을 자동 계산한다
- [ ] 여러 장의 신용카드를 등록할 수 있다
- [ ] 등록된 카드의 모든 정보를 수정하거나 삭제할 수 있다

> **예시:** 사용기간 1일~말일 / 결제일 다음 달 25일로 등록한 경우,
> 1월 20일에 발생한 거래 → 1월 사용기간에 해당 → 현금 유출일 = 2월 25일로 자동 계산됨

---

**US-007**
**제목:** 은행 계좌 등록
**스토리:** 나는 **사용자**로서, 은행 계좌를 결제 수단으로 등록하고 싶다, 왜냐하면 계좌에서 직접 결제한 거래를 태그하고 싶기 때문이다.
**우선순위:** Must Have (필수)

**인수 조건:**
- [ ] 계좌 이름(예: "카카오뱅크 입출금")을 입력해 은행 계좌를 등록할 수 있다
- [ ] 은행 계좌 거래는 결제일 = 거래일로 처리된다 (별도 결제 주기 없음)
- [ ] 여러 개의 은행 계좌를 등록할 수 있다

---

**US-008**
**제목:** 거래에 결제 수단 태그
**스토리:** 나는 **사용자**로서, 거래마다 어떤 카드나 계좌를 사용했는지 태그하고 싶다, 왜냐하면 결제 수단별 지출을 추적하고 싶기 때문이다.
**우선순위:** Must Have (필수)

**인수 조건:**
- [ ] 거래 입력 화면에 등록된 결제 수단 드롭다운이 표시된다
- [ ] 거래당 하나의 결제 수단을 선택할 수 있다
- [ ] 거래 내역 목록에서 결제 수단이 표시된다
- [ ] 결제 수단별로 거래 내역을 필터링할 수 있다

## 기능 3: 대시보드 — 이중 뷰 (Dashboard — Dual View)

---

**US-009**
**제목:** 이중 뷰 대시보드 보기
**스토리:** 나는 **사용자**로서, 발생주의 뷰와 현금 뷰를 나란히 보고 싶다, 왜냐하면 이번 달 비용 귀속 금액과 실제 현금 유출 금액을 동시에 비교하고 싶기 때문이다.
**우선순위:** Must Have (필수)

**인수 조건:**
- [ ] 대시보드가 현재 월을 기본으로 열린다
- [ ] PC(데스크톱)에서: 발생주의 뷰와 현금 뷰가 나란히 표시된다
- [ ] 모바일에서: 발생주의 탭과 현금 탭으로 전환해서 볼 수 있다
- [ ] 각 뷰에서 총 수입, 총 지출, 순 잔액이 표시된다
- [ ] 분할 거래에 대해 두 뷰의 값이 서로 다르게 (그리고 각각 정확하게) 표시된다

---

**US-010**
**제목:** 다른 월로 이동
**스토리:** 나는 **사용자**로서, 과거 및 미래 월로 이동하고 싶다, 왜냐하면 지난 내역을 검토하거나 앞으로의 재무를 미리 확인하고 싶기 때문이다.
**우선순위:** Must Have (필수)

**인수 조건:**
- [ ] 화살표 버튼으로 이전 달 / 다음 달로 이동할 수 있다
- [ ] 대시보드가 해당 월의 데이터로 업데이트된다
- [ ] 미래 월에는 예정 거래 기반의 예측 데이터가 "예측" 표시와 함께 보인다
- [ ] 월 선택기(달력)로 특정 월로 바로 이동할 수 있다

---

## 기능 4: 현금 흐름 예측 (Cash Flow Projection)

---

**US-011**
**제목:** 미래 예정 거래 입력
**스토리:** 나는 **사용자**로서, 앞으로 발생할 것이 예상되는 거래를 미리 입력하고 싶다, 왜냐하면 예측 차트에 실제 예정 비용이 반영되길 원하기 때문이다.
**우선순위:** Must Have (필수)

**인수 조건:**
- [ ] 일반 거래와 동일한 방식으로 미래 거래를 추가할 수 있다 (별도 "예정" 플래그 없음 — 시스템이 날짜만으로 자동 분류)
- [ ] 거래 날짜가 오늘 이후면 자동으로 "예정", 날짜가 지나면 자동으로 "실적"으로 전환된다
- [ ] 예정 거래는 거래 내역에서 시각적으로 구분된다 (다른 색상 또는 라벨)
- [ ] 예정 거래 추가 즉시 예측 차트가 업데이트된다
- [ ] 예정 거래는 과거 달의 실적 데이터에 포함되지 않는다
- [ ] 예정 거래의 날짜가 지났는데 수정되지 않은 경우, 다음 대시보드 진입 시 시스템이 묻는다: *"이 거래가 실제로 발생했나요?"* — 사용자는 확정(실적 전환), 수정(날짜/금액 변경), 삭제 중 선택 가능
- [ ] 사용자가 응답하기 전까지 해당 거래는 내역 목록에 표시되어 잊지 않도록 한다

---

**US-012**

- [ ] 카테고리별 금액을 퍼센트 또는 고정 금액으로 조정할 수 있다
- [ ] 조정 즉시 예측 차트가 실시간으로 업데이트된다
- [ ] 가상 시나리오 모드임을 명확히 알 수 있는 시각적 표시가 있다 (예: 배너, 배경색 변경)
- [ ] 모드 종료 시 모든 원본 데이터가 복원되며, 아무것도 저장되지 않는다

## 기능 5: 예산 관리 (Budget Management)

---

**US-014**
**제목:** 카테고리별 월 예산 설정
**스토리:** 나는 **사용자**로서, 각 카테고리의 월 지출 한도를 설정하고 싶다, 왜냐하면 특정 항목에서 과소비가 발생하는 것을 미리 알고 싶기 때문이다.
**우선순위:** Must Have (필수)

**인수 조건:**
- [ ] 각 카테고리별로 월 한도 금액을 설정할 수 있다
- [ ] 예산 설정은 변경 전까지 다음 달에도 자동으로 유지된다
- [ ] 특정 카테고리의 예산 한도를 삭제할 수 있다
- [ ] 예산이 설정되지 않은 카테고리에는 경고가 표시되지 않는다

---

**US-015**
**제목:** 예산 진행률 확인 및 경고 받기
**스토리:** 나는 **사용자**로서, 예산 대비 사용 현황을 확인하고 한도에 가까워지면 경고를 받고 싶다, 왜냐하면 예산 초과 전에 지출을 조정할 수 있기 때문이다.
**우선순위:** Must Have (필수)

**인수 조건:**
- [ ] 카테고리별 사용 비율을 프로그레스 바로 확인할 수 있다
- [ ] 예산의 80%에 도달하면 프로그레스 바가 노란색으로 변한다
- [ ] 예산을 초과하면 프로그레스 바가 빨간색으로 변한다
- [ ] 경고는 대시보드와 예산 설정 페이지 모두에서 표시된다

## 기능 8: 사용자 계정 (User Account)

---

**US-020**
**제목:** 이메일로 회원가입 및 기본 통화 설정
**스토리:** 나는 **신규 사용자**로서, 이메일로 계정을 만들고 통화를 설정하고 싶다, 왜냐하면 내 로컬 통화로 재무를 추적하고 싶기 때문이다.
**우선순위:** Must Have (필수)

**인수 조건:**
- [ ] 이메일과 비밀번호(최소 8자)로 회원가입할 수 있다
- [ ] 회원가입 중 드롭다운에서 기본 통화를 선택할 수 있다
- [ ] 모든 거래에 이 통화가 기본으로 적용된다
- [ ] 가입 후 확인 이메일이 발송된다

---

**US-021**
**제목:** 로그인 및 로그아웃
**스토리:** 나는 **기존 사용자**로서, 로그인해서 내 데이터를 보고 사용 후 로그아웃하고 싶다, 왜냐하면 내 재무 데이터가 비공개로 유지되길 원하기 때문이다.
**우선순위:** Must Have (필수)

**인수 조건:**
- [ ] 이메일과 비밀번호로 로그인할 수 있다
- [ ] 로그인 후 대시보드로 바로 이동한다
- [ ] 어떤 페이지에서든 메뉴에서 로그아웃할 수 있다
- [ ] 로그아웃 후 다시 로그인하지 않으면 데이터에 접근할 수 없다

---

**US-022**
**제목:** 비밀번호 재설정
**스토리:** 나는 **비밀번호를 잊어버린 사용자**로서, 이메일로 비밀번호를 재설정하고 싶다, 왜냐하면 내 계정에 다시 접근해야 하기 때문이다.
**우선순위:** Must Have (필수)

**인수 조건:**
- [ ] 로그인 페이지에서 "비밀번호 찾기"를 클릭할 수 있다
- [ ] 이메일을 입력하면 2분 이내에 재설정 링크가 발송된다
- [ ] 재설정 링크는 1시간 후 만료된다
- [ ] 재설정 완료 후 새 비밀번호로 즉시 로그인할 수 있다

---

**US-023**
**제목:** 계정 설정 수정
**스토리:** 나는 **사용자**로서, 이메일, 비밀번호, 기본 통화를 설정에서 변경하고 싶다, 왜냐하면 계정 정보를 최신 상태로 유지하고 싶기 때문이다.
**우선순위:** Should Have (중요)

**인수 조건:**
- [ ] 이메일을 변경할 수 있다 (비밀번호 재확인 필요)
- [ ] 비밀번호를 변경할 수 있다 (현재 비밀번호 확인 필요)
- [ ] 기본 통화를 변경할 수 있다 — 이후 거래에만 적용됨. 과거 거래는 원래 통화 그대로 유지되며 소급 변환되지 않는다
- [ ] 여러 통화 거래가 공존할 경우, 대시보드와 리포트는 통화별 합계를 별도로 표시한다 (예: "KRW 합계: ₩1,000,000  |  USD 합계: $500") — 혼합/환산 합계는 표시하지 않음
- [ ] 통화 변경 확정 전, 과거 거래는 기존 통화로 유지된다는 경고가 표시된다
- [ ] 각 변경 사항 저장 후 성공 메시지가 표시된다

## 기능 9: AI 스마트 가져오기 — 캡처 사진 업로드

---

**US-024**
**제목:** 캡처 사진 업로드로 다수 거래 자동 추출
**스토리:** 나는 **사용자**로서, 은행 또는 카드사 앱의 스크린샷을 업로드하고 싶다, 왜냐하면 AI가 이미지 속 거래 내역을 자동으로 읽어줘서 하나씩 직접 입력하는 수고를 덜고 싶기 때문이다.
**우선순위:** Should Have (중요)

**인수 조건:**
- [ ] 메인 네비게이션 또는 거래 입력 화면에서 스마트 가져오기 기능에 접근할 수 있다
- [ ] JPG 또는 PNG 형식의 스크린샷 이미지를 1장 업로드할 수 있다
- [ ] 업로드 후 AI 처리 중 로딩 표시가 나타난다
- [ ] AI는 이미지에서 각 거래의 다음 항목을 추출한다: 날짜, 가맹점명/내용, 금액, 추천 카테고리
- [ ] AI가 특정 필드를 명확히 읽지 못한 경우, 해당 항목은 조용히 건너뛰지 않고 "확인 필요" 표시와 함께 노출된다
- [ ] 이미지에서 인식 가능한 거래가 없으면 명확한 오류 메시지가 표시된다

---

**US-025**
**제목:** AI 추출 항목 검토, 수정 후 일괄 저장
**스토리:** 나는 **사용자**로서, AI가 추출한 항목을 저장 전에 반드시 검토하고 싶다, 왜냐하면 AI가 잘못 읽은 내용을 수정해 정확한 거래만 기록에 추가하고 싶기 때문이다.
**우선순위:** Should Have (중요)

**인수 조건:**
- [ ] AI 추출 완료 후 검토 화면에 감지된 모든 거래가 리스트로 표시된다
- [ ] 각 항목에는 날짜, 가맹점명/내용, 금액, 추천 카테고리, 귀속 월, 결제 수단이 표시된다
- [ ] 저장 전 각 항목의 모든 필드를 수정할 수 있다
- [ ] 원하지 않는 항목은 개별 삭제할 수 있다
- [ ] 체크박스로 항목을 선택/해제할 수 있으며, 선택된 항목만 저장된다
- [ ] "확인 필요" 표시 항목은 시각적으로 강조되며, 확인 또는 삭제 처리 전까지 저장할 수 없다
- [ ] "가져오기" 버튼 한 번으로 선택된 모든 항목이 일괄 저장된다
- [ ] 저장 완료 후 가져온 거래들이 거래 내역에 즉시 반영되고 대시보드가 업데이트된다
